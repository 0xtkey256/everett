Everett

CI is red? Try 32 fixes at once. Keep only what the tests prove.

When your tests fail, Everett opens 32 parallel worlds — isolated sandboxes on Daytona — and an open AI model on our own Nosana GPU writes a different fix in each. Every world runs the full test suite; only the fix that passes everything is kept.

Watch a real run python-slugify run
  1. 1CI goes red

    A test fails after a change. Normally someone stops, reads logs and guesses.

  2. 232 worlds, 32 fixes

    Each world is an isolated Daytona sandbox with its own copy of the code and one AI-written fix.

  3. 3The tests decide

    The fix that passes every test — and breaks nothing else — is merged. The other 31 are thrown away.

Today's example comes from our world, satellite imagery: one wrong line makes a map-tile library send Tokyo to Antarctica. Every world shows the satellite image its fix would fetch.

Daytona

Each world runs in an isolated Daytona sandbox started from a pre-built snapshot (Python, repo, dependencies): 1 base + 8 sandboxes × 4 worlds = 32 worlds within a 10-vCPU account. A world starts in ~2 s and runs the full test suite in under 2 s; every sandbox is labelled and deleted after the run. Built for sandbox.fork() — a copy-on-write clone of a ready world.

Nosana

The AI runs on one NVIDIA RTX 3090 (24 GB) rented from Nosana's decentralized GPU network. Our Nosana job is a container spec: vLLM 0.8.5 serving Qwen2.5-Coder-7B-Instruct behind an OpenAI-compatible HTTPS endpoint, health-checked on /v1/models. One request returns 8 different patches (n=8) in ~2.3 s — vLLM computes the shared prompt once and samples 8 fixes in parallel. $0.19/h: a whole run ≈ 35k tokens ≈ $0.003.
